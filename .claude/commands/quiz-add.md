카테고리 4개(한국사, 세계지리, 과학, 예술과 문화)에 새 문항을 `n`개씩 만든다. 그래서 카테고리마다 문항 수가 같게 유지된다.

## 지켜야 할 것

- 승인 전에는 어떤 파일도 만들거나 고치지 않는다.
  - 문항 초안은 대화에만 보여 준다. 초안을 파일로 저장하지 않는다.
  - 사용자가 "승인", "넣어 줘"처럼 분명히 승인한 뒤에만 questions.js를 고친다. 질문이나 수정 요청은 승인이 아니다.
- 승인 뒤에도 questions.js 말고는 고치지 않고, questions.js에서도 새 문항을 더하는 것 말고는 바꾸지 않는다. 기존 문항과 첫 줄 주석은 그대로 둔다.
- 커밋하지 않는다.
- 카테고리마다 더하는 문항 수는 언제나 같아야 한다. 어떤 카테고리의 문항이 하나라도 빠지면 그 자리를 새 문항으로 채우고, 채우지 못하면 아무것도 넣지 않는다.
- 문항 작성 규칙의 정본은 CLAUDE.md다. 이 파일의 설명과 CLAUDE.md가 다르면 CLAUDE.md를 따른다.

## 인수

- `$ARGUMENTS`가 1 이상의 정수 하나면 그 값을 `n`으로 쓴다.
- 비었거나 정수가 아니거나 0 이하면 아무것도 하지 않고 "사용법: /quiz-add <n> (예: /quiz-add 2)"라고 알린 뒤 멈춘다.

## 순서

### 1. 규칙과 현재 문항 읽기

1. CLAUDE.md의 "문항 작성 규칙" 10개와 PRD.md 6.1항(데이터 형식), 6.2항(출처 표기)을 읽는다.
2. questions.js 전체를 읽는다.
3. 아래 "Node 형식 검사"를 실행한다.
   - 실패하면(카테고리마다 문항 수가 다른 경우 포함) 새 문항을 만들지 않고 실패 내용을 보고한 뒤 멈춘다.
4. 카테고리별 마지막 번호를 확인해 새 id를 정한다.
   - 약자: 한국사 `kh`, 세계지리 `wg`, 과학 `sc`, 예술과 문화 `ac`
   - 번호는 마지막 번호 다음부터 두 자리로 매긴다(예: `kh-10` 다음은 `kh-11`). 100번부터는 세 자리로 쓴다.

### 2. 문항 만들기

카테고리마다 `n`개씩, 모두 `4 × n`개를 만든다.

- 기존 문항과 겹치지 않게 한다. 같은 사실을 묻거나, 정답과 묻는 대상이 같은 문항은 쓰지 않는다. 새 문항끼리도 겹치지 않게 한다.
- CLAUDE.md 규칙 10개를 모두 지킨다. 특히 다음을 한 문항씩 확인한다.
  - 정답이 유일하고, 오답 3개가 어떤 기준으로도 정답이 될 수 없음(규칙 1)
  - 최상급 표현을 쓰면 기준과 시점을 문제 문장에 적음(규칙 2)
  - 오답 3개가 정답과 같은 유형이고 그럴듯함(규칙 7)
  - 보기 4개의 길이와 형식이 비슷함(규칙 8)
  - 부정문, "모두 맞음" 같은 보기를 쓰지 않음(규칙 9, 10)
- 기존 문항의 말투를 따른다. 문제 문장은 "~은?"으로 끝내고, 해설은 한 줄로 "~함", "~임"으로 끝낸다.

### 3. 출처를 실제로 열어 확인하기

검색 결과의 요약이나 내가 기억하는 내용만으로 확인을 끝내지 않는다. 문항마다 다음을 한다.

1. WebSearch로 자료를 찾고, WebFetch로 그 페이지를 실제로 연다.
2. 문제 문장, 정답, 해설에 쓴 사실(연도, 이름, 수치 등)을 서로 다른 출처 2곳 이상의 본문에서 확인한다(규칙 4).
   - 공공기관, 박물관·기관 공식 누리집, 백과사전(예: 한국민족문화대백과사전, 우리역사넷)을 우선한다.
   - 같은 자료를 옮겨 실은 페이지는 서로 다른 출처로 치지 않는다.
3. 오답 3개가 정답이 될 수 없다는 것도 출처로 확인한다. 예를 들어 "1592년 한산도 대첩"을 물으면 오답 인물이 그 전투를 이끌지 않았음을 확인한다.
4. 다음 경우에는 그 문항을 버리고 다른 사실로 새 문항을 만들어 1번부터 다시 확인한다.
   - 페이지가 열리지 않거나, 본문에서 그 사실을 찾지 못함
   - 출처끼리 값이 다름(그 값은 문제와 해설에 쓰지 않음)
   - 출처 2곳을 찾지 못함
5. 확인한 날짜는 아래 명령으로 얻은 한국 시간 날짜를 쓴다.

```bash
node -e "console.log(new Date(Date.now() + 9 * 3600e3).toISOString().slice(0, 10))"
```

6. 확인한 출처 2곳을 출처 A, 출처 B로 정해 두고, `source`에는 그 가운데 근거가 더 분명한 1곳만 기존 문항과 같은 형식(`자료명, URL, 확인한 날짜`)으로 적는다.
   - 근거가 더 분명한 곳: 문제 문장, 정답, 해설에 쓴 사실을 본문에서 더 직접, 더 많이 밝힌 곳. 비슷하면 공공기관·기관 공식 자료를 고른다.
   - 예: `"한국민족문화대백과사전 「훈민정음」, https://encykorea.aks.ac.kr/Article/E0065806, 2026-10-09"`
   - 자료명은 기존 문항처럼 `기관·사전 이름 「항목명」`으로 쓰고, 영문 자료는 `기관 이름 "항목명"`으로 쓴다.
   - `source`에 적지 않은 출처는 파일에 남기지 않고 4단계 검수표에만 보여 준다.

### 4. 초안 보여 주고 승인 기다리기

다음 형식으로 보여 준 뒤 멈추고 사용자의 답을 기다린다.

1. 첫 줄에 "카테고리 4개에 n개씩, 모두 4×n문항을 만들었음. 넣으면 카테고리마다 X문항, 모두 Y문항이 됨."처럼 적는다.
2. 카테고리마다 검수표를 하나씩 보여 준다.

| id | 문제 문장 | 보기 (정답은 **굵게**) | 해설 | 출처 A | 출처 B | 두 곳이 일치 | source |
|---|---|---|---|---|---|---|---|
| (예시) kh-11 | ... | **세종** / 태종 / 세조 / 성종 | ... | 자료명(URL) — 확인한 사실 | 자료명(URL) — 확인한 사실 | 일치: 1443년 창제, 세종 | A |

   - "출처 A", "출처 B" 칸에는 자료명과 URL, 그 페이지에서 무엇을 확인했는지 짧게 적는다.
   - "두 곳이 일치" 칸에는 "일치: "에 이어 두 출처가 같은 값으로 밝힌 사실(연도, 이름, 수치 등)을 적는다. 값이 다른 사실이 하나라도 있는 문항은 3단계 4번에 따라 버렸으므로 이 표에 나오지 않는다.
   - "source" 칸에는 `source`에 적은 출처가 A인지 B인지 적는다.
3. 표 아래에 questions.js에 넣을 코드를 카테고리별 ```js 블록으로 보여 준다. 형식은 PRD 6.1항과 기존 문항을 따른다.
4. 마지막에 "확인하지 못한 것"을 적는다. 없으면 "없음"이라고 적는다.
5. "승인하면 questions.js에 넣겠음. 고칠 문항이 있으면 id와 함께 알려 줘."라고 묻고 멈춘다.

사용자가 고쳐 달라고 하면:

- 고친 문항은 3단계(출처 확인)를 다시 거친 뒤 4단계 형식으로 다시 보여 주고 다시 승인을 기다린다.
- 고친 뒤에는 정답, 보기, 해설이 서로 맞는지 다시 확인한다(규칙 6).
- 문항을 빼 달라고 하면 같은 카테고리에 대신할 문항을 새로 만든다. 사용자가 개수를 줄이자고 하면 카테고리 4개를 모두 같은 개수로 줄인다.

### 5. 승인 뒤 넣기

1. Edit로 각 카테고리의 마지막 문항 바로 뒤에 그 카테고리의 새 문항을 id 순서대로 넣는다. 카테고리 순서와 묶음은 기존대로 유지한다.
2. "Node 형식 검사"를 다시 실행한다. 기대 출력은 `문항 검사 통과: Y문항`(Y = 원래 문항 수 + 4×n)으로 시작하고, 괄호 안의 카테고리별 문항 수가 모두 같다.
   - 실패하면 원인을 고치고 다시 실행한다. 고친 내용은 보고에 적는다.
3. 다음을 보고한다.
   - 넣은 문항 id 목록과 카테고리별·전체 문항 수
   - Node 검사 결과(출력 그대로)
   - 커밋하지 않았다는 것

## Node 형식 검사

검사 명령은 실행만 하고 파일로 남기지 않는다(PRD 6.3항).

```bash
node - <<'EOF'
const fs = require("fs"), vm = require("vm");
const ctx = {};
vm.runInNewContext(fs.readFileSync("questions.js", "utf8") + "\nthis.Q = QUESTIONS;", ctx);
const cats = ["한국사", "세계지리", "과학", "예술과 문화"];
const prefix = { "한국사": "kh", "세계지리": "wg", "과학": "sc", "예술과 문화": "ac" };
const errs = [];
const counts = cats.map(c => ctx.Q.filter(q => q.category === c).length);
if (counts[0] === 0 || counts.some(n => n !== counts[0]))
  errs.push(`카테고리마다 문항 수가 같지 않음: ${cats.map((c, i) => `${c} ${counts[i]}`).join(", ")}`);
const ids = ctx.Q.map(q => q.id);
for (const id of ids.filter((id, i) => ids.indexOf(id) !== i)) errs.push(`${id}: id가 겹침`);
for (const q of ctx.Q) {
  if (!cats.includes(q.category)) errs.push(`${q.id}: 카테고리 ${q.category}`);
  else if (!new RegExp(`^${prefix[q.category]}-\\d{2,}$`).test(q.id)) errs.push(`${q.id}: id 형식이 카테고리와 맞지 않음`);
  if (q.choices.length !== 4 || new Set(q.choices).size !== 4) errs.push(`${q.id}: 보기 4개가 서로 다르지 않음`);
  if (q.choices.filter(c => c === q.answer).length !== 1) errs.push(`${q.id}: 정답이 보기에 정확히 1번 나오지 않음`);
  if (!q.explanation?.trim() || !q.source?.trim()) errs.push(`${q.id}: 해설 또는 출처가 비어 있음`);
}
console.log(errs.length ? errs.join("\n") : `문항 검사 통과: ${ctx.Q.length}문항 (${cats.map((c, i) => `${c} ${counts[i]}`).join(", ")})`);
process.exitCode = errs.length ? 1 : 0;
EOF
```
